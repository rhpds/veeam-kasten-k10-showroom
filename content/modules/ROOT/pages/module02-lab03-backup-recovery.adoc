== 2. Simulated Attack

[arabic]
. Return to the Pacman tab in your browser and click "`View Highscore List`" or if the game is playing, hit the space bar and click *High Score*
+
.Leaderboard
image::module02-lab03-backup-recovery/pacman_leaderboard.png[Leaderboard]
. Return to the OpenShift Console tab and from the web terminal, drop the `pacman` database from MongoDB that holds your highscore:
+
[source,bash,role=execute,subs="attributes"]
----
export MONGODB_ROOT_PASSWORD=$(oc get secret -n kasten-lab-{user}-pacman pacman-mongodb -o jsonpath="{.data.mongodb-root-password}" | base64 --decode)
oc exec -it statefulset/pacman-mongodb -n kasten-lab-{user}-pacman -- mongosh pacman --authenticationDatabase admin -u root -p $MONGODB_ROOT_PASSWORD --eval 'db.dropDatabase();'
----
+
====
[IMPORTANT]

This command is simulating a data compromise event, which could be something as innocent as an administrator ++>++ accidentally dropping a table or database, or as nefarious as a ransomware attack
====
. Return to the Pacman tab in your browser and refresh the page. Click *High Score*. *!!OH NO YOUR HIGH SCORE IS GONE!!*
+
.no high scores
image::module02-lab03-backup-recovery/no_highscores.png[no high scores]

== 3. Recover Our Score

[arabic]
. No fear, let’s restore our backup. Click on the Kasten tab in your browser and return to the main dashboard by clicking on **Dashboard**
. Click *Compliant* in the Applications modal.
+
.Compliant
image::module02-lab03-backup-recovery/compliant.png[Compliant]
. Click the *_..._* menu for the `kasten-lab-{user}-pacman` application and select *_Restore_*
+
.Restore
image::module02-lab03-backup-recovery/restore.png[Restore]
. You will be taken to the *_Restore Points_* page, filtered to your application. Click the *_..._* menu for the most recent RestorePoint of type *_Snapshot_* and select *_Restore_*
+
.Select Restore Point
image::module02-lab03-backup-recovery/perform_restore.png[Select Restore Point]
+
====
[IMPORTANT]
There are two types of RestorePoint from which to restore. The *_Exported_* RestorePoint is stored on our S3 object storage, while the *_Snapshot_* RestorePoint is a local snapshot on the cluster. In the event of an accidental deletion, restoring from the local snapshot is sufficient, but if we were facing the result of a ransomware attack we would likely want to restore from the S3 bucket. For the purposes of this lab, we’ll use the local snapshot since restore time will be slightly faster.
====
. Under *_Optional Restore Settings_*, check *_Data-Only Restore_*
+
.Data-Only Restore
image::module02-lab03-backup-recovery/volume_only_restore.png[Data-Only Restore]
+
====
[NOTE]
A *_Data-Only Restore_* restores only the volume data for the existing workloads in the namespace - in this case the MongoDB PersistentVolumeClaim - without overwriting the Deployment, StatefulSet, Secrets, ConfigMaps, or other resources. 
Alternatively, *_Volume-Clones Restore_* restores a timestamp-appended copy of the volumes alongside the existing ones, which is useful for recovering individual files without disrupting the running application.
====
. Click *Restore*.
. Click *Restore* when prompted to confirm restoring only data for the application.
. Return to the Dashboard by clicking on the **Dashboard** link in the upper left corner
. Click on the running Restore Action to monitor the action
. After a minute or two all phases should complete successfully
+
.Restore Completed
image::module02-lab03-backup-recovery/restore_completed.png[Restore Completed]
. Return to the pacman tab and refresh the browser tab. Click *High Score*. Our high score is back! *REJOICE!*
+
.Leaderboard
image::module02-lab03-backup-recovery/pacman_leaderboard.png[Leaderboard]

== 4. Takeaways

* Kasten automatically interrogates and detects namespaces on the cluster
* Backup policies can be configured quickly on a per-namespace basis for containerized applications, or on a per-VM basis for Virtual Machines
* We can easily monitor actions via the Kasten UI
* We have granular control on how we restore from backup, including whether from on-cluster or exported storage
* We have granular control over what we recover, such as restoring only volume data with a *_Data-Only Restore_*
